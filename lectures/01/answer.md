# 第1回 解答

## 演習

- 質問：RAGとは何ですか？
- 回答（要約）：RAG（Retrieval-Augmented Generation／検索拡張生成）は、質問に関連する外部文書やデータを検索し、その内容をLLMに渡して回答を生成する仕組み。社内資料や更新された情報を活用でき、回答の根拠を示しやすくなる。
- モデル間の違い・気づき：2モデルとも検索・拡張・生成の流れや、社内情報・最新情報に使える点を説明した。`gemini-3.5-flash-lite` は回ごとに2段階または3段階で仕組みを説明し、`gemini-3.5-flash` は3段階の説明と試験のたとえを使う傾向があった。どの回答も、検索の質が低い場合などには誤りうる点への言及は十分でないため、RAGが正確性を保証するわけではない。
- トークン数（入力 / 出力）：
    - 入力：すべて7トークン。
    - 出力：`gemini-3.5-flash-lite` は 694 / 633 / 635、`gemini-3.5-flash` は 780 / 765 / 751。

## 宿題

- 取り組んだレベル：基礎
- やったこと：同じ質問「RAGとは何ですか？」を、`gemini-3.5-flash-lite` と `gemini-3.5-flash` で各3回実行した。temperatureはモデル既定値。
- 結果：
  - 2モデルとも、外部資料から関連情報を検索し、その情報を使って回答を生成する仕組みと説明した。
  - `gemini-3.5-flash-lite` の出力トークン数は 694 / 633 / 635、`gemini-3.5-flash` は 780 / 765 / 751。入力はいずれも各回7トークン。
  - 回答全文：[RAGの質問：モデル別の実験回答](rag-responses.md)
- 気づき・疑問：基本的な定義は共通していた一方、説明の段階数やたとえ、メリットの挙げ方に違いがあった。RAGは回答の正確性を保証するものではなく、検索結果や参照データの質を確認する必要がある。
